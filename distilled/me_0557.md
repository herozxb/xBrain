## 1. Two Pointers Technique

```python
# PROBLEM: Find a pair of elements in a sorted array that sum to a target value
# TIME: O(n) SPACE: O(1)
def two_sum_sorted(arr, target):
    """
    Use two pointers from both ends to find target sum.
    Optimal for sorted arrays - only requires single pass.
    """
    left, right = 0, len(arr) - 1  # Initialize pointers at array bounds
    
    while left < right:  # Continue until pointers meet
        current_sum = arr[left] + arr[right]  # Calculate current pair sum
        
        if current_sum == target:  # Found target sum
            return [arr[left], arr[right]]  # Return the pair
        elif current_sum < target:  # Sum too small - need larger value
            left += 1  # Move left pointer right to increase sum
        else:  # Sum too large - need smaller value
            right -= 1  # Move right pointer left to decrease sum
    
    return None  # No pair found
```

**Why**: Two pointers reduce time complexity from O(n²) brute force to O(n). Works only on sorted data. Commonly used in array problems involving pairs, triplets, or palindromes.

## 2. Sliding Window Pattern

```python
# PROBLEM: Find maximum sum of any contiguous subarray of size k
# TIME: O(n) SPACE: O(1)
def max_sum_subarray(arr, k):
    """
    Sliding window technique for fixed-size window problems.
    Reuse computations from previous window instead of recalculating.
    """
    if len(arr) < k:  # Edge case: array smaller than window
        return None
    
    # Calculate sum of first window
    window_sum = sum(arr[:k])  # Initial window sum - O(k) operation
    max_sum = window_sum  # Track maximum sum found
    
    # Slide window across array - O(n-k) iterations
    for i in range(len(arr) - k):
        # Efficient update: subtract outgoing element, add incoming element
        window_sum = window_sum - arr[i] + arr[i + k]
        max_sum = max(max_sum, window_sum)  # Update maximum if needed
    
    return max_sum
```

**Why**: Converts O(n×k) naive approach to O(n). Window slides by removing leftmost and adding rightmost element. Essential for substring, subarray problems with constraints.

## 3. Binary Search

```python
# PROBLEM: Find target element index in sorted array, or return insertion point
# TIME: O(log n) SPACE: O(1)
def binary_search(arr, target):
    """
    Divide and conquer search on sorted data.
    Eliminates half of remaining elements each iteration.
    Returns index if found, or insertion point if not found.
    """
    left, right = 0, len(arr) - 1  # Search boundaries
    
    while left <= right:  # Continue while search space exists
        mid = left + (right - left) // 2  # Avoid overflow, find middle
        # Note: (right - left) // 2 prevents integer overflow in other languages
        
        if arr[mid] == target:  # Target found
            return mid  # Return index
        elif arr[mid] < target:  # Target in right half
            left = mid + 1  # Discard left half (including mid)
        else:  # Target in left half
            right = mid - 1  # Discard right half (including mid)
    
    return left  # Insertion point for target (left > right)
```

**Why**: Logarithmic time complexity makes it ideal for large datasets. Requires sorted data. Foundation for many search-based algorithms. Used in database indexes, finding boundaries, and optimization problems.

## 4. Merge Sort

```python
# PROBLEM: Sort an array using divide and conquer
# TIME: O(n log n) SPACE: O(n)
def merge_sort(arr):
    """
    Divide array into halves recursively until single elements,
    then merge sorted halves back together.
    Stable sort - maintains relative order of equal elements.
    """
    if len(arr) <= 1:  # Base case: single element or empty
        return arr  # Already sorted
    
    # Divide: split array into two halves
    mid = len(arr) // 2  # Find middle point
    left = arr[:mid]  # Left half
    right = arr[mid:]  # Right half
    
    # Conquer: recursively sort each half
    left_sorted = merge_sort(left)  # Sort left half
    right_sorted = merge_sort(right)  # Sort right half
    
    # Combine: merge two sorted halves
    return merge(left_sorted, right_sorted)  # Merge step


def merge(left, right):
    """Merge two sorted arrays into one sorted array."""
    result = []  # Merged result
    i = j = 0  # Pointers for left and right arrays
    
    # Compare elements from both arrays, add smaller to result
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:  # Left element is smaller or equal
            result.append(left[i])  # Add from left
            i += 1  # Move left pointer
        else:  # Right element is smaller
            result.append(right[j])  # Add from right
            j += 1  # Move right pointer
    
    # Append remaining elements (one array is exhausted)
    result.extend(left[i:])  # Add remaining left elements
    result.extend(right[j:])  # Add remaining right elements
    
    return result
```

**Why**: Guaranteed O(n log n) regardless of input distribution. Stable sort preserves order of duplicates. Predictable performance but requires extra O(n) space. Used in external sorting when data doesn't fit in memory.

## 5. BFS (Breadth-First Search)

```python
# PROBLEM: Find shortest path (minimum edges) from start to target in unweighted graph
# TIME: O(V + E) SPACE: O(V) where V=vertices, E=edges
from collections import deque

def bfs_shortest_path(graph, start, target):
    """
    Explore graph level by level from start node.
    Guarantees shortest path in unweighted graphs.
    Uses queue (FIFO) for frontier nodes.
    """
    if start == target:  # Edge case: start is target
        return [start]
    
    queue = deque([[start]])  # Queue stores paths, start with [start]
    visited = {start}  # Track visited nodes to avoid cycles
    
    while queue:  # Continue until queue is empty
        path = queue.popleft()  # Get oldest path (FIFO order)
        node = path[-1]  # Current node is last in path
        
        # Explore all neighbors
        for neighbor in graph.get(node, []):  # Get neighbors (empty list if none)
            if neighbor not in visited:  # Only visit unvisited nodes
                new_path = path + [neighbor]  # Extend path with neighbor
                
                if neighbor == target:  # Found target
                    return new_path  # Return shortest path
                
                visited.add(neighbor)  # Mark as visited
                queue.append(new_path)  # Add new path to queue
    
    return None  # No path exists
```

**Why**: BFS explores nodes level-by-level, ensuring shortest path in unweighted graphs. Used in social networks (degrees of separation), puzzle solving (minimum moves), and web crawling. Memory-intensive for wide graphs.

## 6. DFS (Depth-First Search)

```python
# PROBLEM: Detect if a cycle exists in a directed graph
# TIME: O(V + E) SPACE: O(V) 
def has_cycle(graph):
    """
    DFS explores as deep as possible before backtracking.
    Detect cycles using recursion stack tracking.
    Returns True if cycle exists, False otherwise.
    """
    visited = set()  # Nodes that have been fully processed
    rec_stack = set()  # Nodes currently in recursion stack
    
    def dfs(node):
        """Recursive DFS helper with cycle detection."""
        visited.add(node)  # Mark node as visited
        rec_stack.add(node)  # Add to recursion stack
        
        # Explore all neighbors
        for neighbor in graph.get(node, []):
            if neighbor not in visited:  # Unvisited node
                if dfs(neighbor):  # Recursive call, propagate True
                    return True
            elif neighbor in rec_stack:  # Back edge found - cycle!
                return True
        
        rec_stack.remove(node)  # Remove from recursion stack (backtrack)
        return False  # No cycle found in this path
    
    # Check all nodes (handle disconnected components)
    for node in graph:
        if node not in visited:
            if dfs(node):  # If cycle found in any component
                return True
    
    return False  # No cycles in entire graph
```

**Why**: DFS uses less memory than BFS for deep graphs. Natural for problems involving paths, cycles, connectivity, and topological sorting. Stack-based (recursive or explicit) approach. Used in maze solving, dependency resolution, and game AI.

## 7. LRU Cache Implementation

```python
# PROBLEM: Design a cache with O(1) get/put that evicts least recently used items
# TIME: O(1) for get/put SPACE: O(capacity)
class Node:
    """Doubly linked list node for O(1) removal."""
    def __init__(self, key=0, val=0):
        self.key = key  # Store key for deletion from hashmap
        self.val = val  # Value stored in cache
        self.prev = None  # Previous node pointer
        self.next = None  # Next node pointer


class LRUCache:
    """
    Combine hashmap (O(1) lookup) with doubly linked list (O(1) reorder).
    Head = most recent, Tail = least recent.
    """
    def __init__(self, capacity):
        self.capacity = capacity  # Maximum cache size
        self.cache = {}  # Hashmap: key -> Node
        
        # Dummy head and tail for easier edge handling
        self.head = Node()  # Most recently used (dummy)
        self.tail = Node()  # Least recently used (dummy)
        self.head.next = self.tail  # Connect head to tail
        self.tail.prev = self.head  # Connect tail to head
        # Initially: head <-> tail (empty list)
    
    def _remove(self, node):
        """Remove node from linked list - O(1)."""
        prev_node = node.prev
        next_node = node.next
        prev_node.next = next_node  # Bypass node
        next_node.prev = prev_node  # Bypass node
    
    def _add_to_head(self, node):
        """Add node right after head (most recent position) - O(1)."""
        node.prev = self.head  # Point back to head
        node.next = self.head.next  # Point to old most recent
        self.head.next.prev = node  # Old most recent points back to node
        self.head.next = node  # Head points forward to node
    
    def get(self, key):
        """Get value and move to most recent position - O(1)."""
        if key not in self.cache:  # Key not in cache
            return -1  # Cache miss
        
        node = self.cache[key]  # Get node from hashmap
        self._remove(node)  # Remove from current position
        self._add_to_head(node)  # Move to most recent
        return node.val  # Return value
    
    def put(self, key, value):
        """Add/update key-value pair, evict LRU if over capacity - O(1)."""
        if key in self.cache:  # Key exists - update
            node = self.cache[key]
            node.val = value  # Update value
            self._remove(node)  # Remove from current position
            self._add_to_head(node)  # Move to most recent
        else:  # New key
            if len(self.cache) >= self.capacity:  # Cache full - evict LRU
                lru_node = self.tail.prev  # LRU is before tail dummy
                self._remove(lru_node)  # Remove from list
                del self.cache[lru_node.key]  # Remove from hashmap
            
            new_node = Node(key, value)  # Create new node
            self.cache[key] = new_node  # Add to hashmap
            self._add_to_head(new_node)  # Add to most recent position
```

**Why**: Combines two data structures to achieve O(1) operations. Hashmap provides fast lookup; doubly linked list maintains recency order. Used in databases, browsers, operating systems for caching. Doubly linked list with dummy nodes simplifies edge cases.

## 8. Trie (Prefix Tree)

```python
# PROBLEM: Efficiently store and search strings with prefix matching
# TIME: O(m) insert/search where m = string length SPACE: O(alphabet_size * total_chars)
class TrieNode:
    """Node in trie with children map and end-of-word flag."""
    def __init__(self):
        self.children = {}  # Map character to child TrieNode
        self.is_end = False  # True if this node ends a word


class Trie:
    """
    Tree structure where each path from root represents a string prefix.
    Efficient for prefix-based searches and autocomplete.
    """
    def __init__(self):
        self.root = TrieNode()  # Root represents empty string
    
    def insert(self, word):
        """Insert word into trie - O(m)."""
        node = self.root  # Start from root
        for char in word:  # Process each character
            if char not in node.children:  # Child doesn't exist
                node.children[char] = TrieNode()  # Create new node
            node = node.children[char]  # Move to child node
        node.is_end = True  # Mark end of word
    
    def search(self, word):
        """Check if exact word exists in trie - O(m)."""
        node = self.root
        for char in word:
            if char not in node.children:  # Character not found
                return False  # Word doesn't exist
            node = node.children[char]
        return node.is_end  # True only if this is end of a word
    
    def starts_with(self, prefix):
        """Check if any word starts with prefix - O(m)."""
        node = self.root
        for char in prefix:
            if char not in node.children:
                return False  # Prefix path doesn't exist
            node = node.children[char]
        return True  # Prefix path exists (may or may not be complete word)
```

**Why**: Space-efficient for storing strings with common prefixes. O(m) search regardless of total number of words. Used in autocomplete, spell checkers, IP routing, and word games. Better than hashmap for prefix-based operations.

## 9. Heap (Priority Queue)

```python
# PROBLEM: Find kth largest element in unsorted array
# TIME: O(n + k log n) or O(n log k) SPACE: O(k)
import heapq

def find_kth_largest(nums, k):
    """
    Use min-heap of size k to track k largest elements.
    Root is kth largest (smallest among top k).
    """
    # Build min-heap with first k elements - O(k)
    heap = nums[:k]
    heapq.heapify(heap)  # Transform list into min-heap in-place
    
    # Process remaining elements - O((n-k) * log k)
    for num in nums[k:]:
        if num > heap[0]:  # Only if larger than smallest in top k
            heapq.heappushpop(heap, num)  # Remove smallest, add new element
            # Equivalent to: heapq.heappop + heapq.heappush but more efficient
    
    return heap[0]  # Root is kth largest


# Alternative: QuickSelect for O(n) average case
import random

def find_kth_largest_quickselect(nums, k):
    """
    QuickSelect: partition-based selection algorithm.
    Average O(n), worst case O(n²). Randomized pivot avoids worst case.
    """
    def partition(left, right, pivot_idx):
        """Partition around pivot, return final pivot position."""
        pivot = nums[pivot_idx]
        nums[pivot_idx], nums[right] = nums[right], nums[pivot_idx]  # Move pivot to end
        store_idx = left  # Position to place next element > pivot
        
        for i in range(left, right):
            if nums[i] > pivot:  # For kth largest, use > (for kth smallest, use <)
                nums[store_idx], nums[i] = nums[i], nums[store_idx]
                store_idx += 1
        
        nums[store_idx], nums[right] = nums[right], nums[store_idx]  # Move pivot to final position
        return store_idx
    
    left, right = 0, len(nums) - 1
    while left <= right:
        pivot_idx = random.randint(left, right)  # Random pivot
        pos = partition(left, right, pivot_idx)
        
        if pos == k - 1:  # Found kth largest (0-indexed)
            return nums[pos]
        elif pos < k - 1:  # Target in right partition
            left = pos + 1
        else:  # Target in left partition
            right = pos - 1
```

**Why**: Heap provides O(1) access to min/max element. Heapsort is O(n log n) in-place. Used in Dijkstra's algorithm, Huffman coding, and streaming top-k problems. QuickSelect is faster on average but not guaranteed.

## 10. Dynamic Programming - Fibonacci

```python
# PROBLEM: Calculate nth Fibonacci number efficiently
# TIME: O(n) SPACE: O(1) with optimization
def fib_dp_optimized(n):
    """
    DP with space optimization - only keep last two values.
    Avoids recalculating subproblems (exponential in naive recursion).
    """
    if n <= 1:  # Base cases: F(0)=0, F(1)=1
        return n
    
    prev2 = 0  # F(i-2)
    prev1 = 1  # F(i-1)
    
    # Build solution bottom-up
    for i in range(2, n + 1):  # F(2) to F(n)
        current = prev1 + prev2  # F(i) = F(i-1) + F(i-2)
        prev2 = prev1  # Shift window forward
        prev1 = current  # Update previous
    
    return prev1  # F(n)


# Matrix exponentiation: O(log n) for very large n
def fib_matrix(n):
    """
    Use matrix exponentiation for O(log n) time complexity.
    [[F(n+1), F(n)], [F(n), F(n-1)]] = [[1,1],[1,0]]^n
    """
    if n <= 1:
        return n
    
    def matrix_mult(A, B):
        """Multiply 2x2 matrices."""
        return [
            [A[0][0]*B[0][0] + A[0][1]*B[1][0], A[0][0]*B[0][1] + A[0][1]*B[1][1]],
            [A[1][0]*B[0][0] + A[1][1]*B[1][0], A[1][0]*B[0][1] + A[1][1]*B[1][1]]
        ]
    
    def matrix_pow(M, p):
        """Fast matrix exponentiation using binary exponentiation."""
        result = [[1, 0], [0, 1]]  # Identity matrix
        while p > 0:
            if p % 2 == 1:  # Odd power
                result = matrix_mult(result, M)
            M = matrix_mult(M, M)  # Square the base
            p //= 2  # Halve the exponent
        return result
    
    base = [[1, 1], [1, 0]]
    result = matrix_pow(base, n)
    return result[0][1]  # F(n) is at position [0][1]
```

**Why**: DP eliminates redundant calculations in overlapping subproblems. Space optimization from O(n) to O(1) when only last k states needed. Matrix exponentiation trades simplicity for logarithmic time. Pattern applies to knapsack, longest common subsequence, etc.
