        title="Communicating iframe">
    </iframe>
    
    <script>
        // Send message to iframe
        const iframe = document.getElementById('myFrame');
        iframe.onload = function() {
            iframe.contentWindow.postMessage(
                { type: 'GREETING', message: 'Hello from parent!' },
                'https://example.com'
            );
        };
        
        // Receive messages from iframe
        window.addEventListener('message', (event) => {
            if (event.origin !== 'https://example.com') return;
            console.log('Received:', event.data);
        });
    </script>

**Why**: `<iframe>` enables embedding external content while `sandbox` attribute provides security isolation, `loading="lazy"` improves performance, and `postMessage` enables safe cross-origin communication.

    <embed

        src="animation.swf"
        width="600"
        height="400"
        title="Flash Animation">
    
    <!-- Embed with fallback content -->
    <object data="video.mp4" width="600" height="400">
        <embed src="video.mp4" width="600" height="400">
        <p>Your browser doesn't support embedded videos. 
           <a href="video.mp4">Download the video</a>.</p>
    </object>
    
    <!-- JavaScript to detect embed support -->
    <script>
        function checkEmbedSupport(mimeType) {
            const embed = document.createElement('embed');
            embed.type = mimeType;
            document.body.appendChild(embed);
            const supported = embed.offsetWidth > 0;
            document.body.removeChild(embed);
            return supported;
        }
        
        console.log('PDF support:', checkEmbedSupport('application/pdf'));
    </script>
</body>
</html>
```
**Why**: `<embed>` is used for plugin-based content like PDFs and SVGs. It's self-closing and simpler than `<object>`, but lacks fallback capabilities. Use `<object>` when fallback content is needed.

        // Access object content (same-origin only)
        const obj = document.getElementById('dataObject');
        obj.onload = function() {
            try {
                const contentDoc = obj.contentDocument;
                console.log('Object loaded:', contentDoc);
            } catch (e) {
                console.log('Cannot access cross-origin content');
            }
        };
        
        // Check if object loaded successfully
        obj.addEventListener('error', () => {
            console.log('Object failed to load');
        });
    </script>
</body>
</html>
```
**Why**: `<object>` is versatile with robust fallback support via nested content. It supports `<param>` children for configuration and can embed any MIME type, making it more flexible than `<embed>` or `<iframe>`.
