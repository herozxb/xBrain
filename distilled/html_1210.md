## 1. html_anchor_hreflang

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Anchor hreflang Attribute</title>
</head>
<body>
    <!-- 
        PROBLEM: Specify language of linked document for SEO and accessibility
        TIME: O(1) SPACE: O(1)
    -->
    
    <!-- hreflang tells search engines the language of the target page -->
    <nav>
        <a href="https://example.com/en/about" hreflang="en" lang="en">About Us (English)</a>
        <a href="https://example.com/es/about" hreflang="es" lang="es">Sobre Nosotros (Español)</a>
        <a href="https://example.com/fr/about" hreflang="fr" lang="fr">À Propos (Français)</a>
        <a href="https://example.com/zh/about" hreflang="zh-CN" lang="zh-CN">关于我们 (中文)</a>
    </nav>
    
    <!-- Link to alternate language versions in head for SEO -->
    <link rel="alternate" hreflang="en" href="https://example.com/en/">
    <link rel="alternate" hreflang="es" href="https://example.com/es/">
    <link rel="alternate" hreflang="x-default" href="https://example.com/">
</body>
</html>
```
**Why**: The `hreflang` attribute improves SEO for multilingual sites by helping search engines understand the language of linked pages and serve appropriate versions to users.

## 2. css_grid_align_items

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>CSS Grid Align Items</title>
    <style>
        /* 
            PROBLEM: Align grid items along the block (column) axis
            TIME: O(1) SPACE: O(1)
        */
        
        .grid-container {
            display: grid;
            grid-template-columns: repeat(3, 1fr);
            height: 300px;
            gap: 10px;
            background: #f0f0f0;
            
            /* Align all items vertically within their grid cells */
            align-items: center;  /* Options: stretch | start | end | center | baseline */
        }
        
        .grid-item {
            padding: 20px;
            background: #3498db;
            color: white;
        }
        
        /* Override alignment for individual items */
        .grid-item.special {
            align-self: end;
            background: #e74c3c;
        }
        
        /* Different align-items values */
        .grid-stretch { align-items: stretch; }  /* Default - fills cell height */
        .grid-start { align-items: start; }      /* Top of cell */
        .grid-end { align-items: end; }          /* Bottom of cell */
        .grid-center { align-items: center; }    /* Center of cell */
        .grid-baseline { align-items: baseline; } /* Text baseline aligned */
    </style>
</head>
<body>
    <div class="grid-container">
        <div class="grid-item">Item 1</div>
        <div class="grid-item special">Item 2 (end)</div>

    </div>
</body>
</html>
```
**Why**: `align-items` in CSS Grid controls the vertical alignment of all grid items within their cells, making it easy to create consistent layouts without individual item styling.

## 3. css_pseudo_class_first_child

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>CSS :first-child Pseudo-class</title>
    <style>
        /* 
            PROBLEM: Style the first element among siblings
            TIME: O(1) SPACE: O(1)
        */
        
        /* Select the first li in any ul */
        ul li:first-child {
            font-weight: bold;
            color: #e74c3c;
        }
        
        /* Select first paragraph in a container */
        article p:first-child {
            font-size: 1.2em;
            color: #2c3e50;
        }
        
        /* Common pattern: remove left margin from first item */
        nav a {
            display: inline-block;
            padding: 10px 15px;
            margin-left: 10px;
            background: #3498db;
            color: white;
            text-decoration: none;
        }
        
        nav a:first-child {
            margin-left: 0;  /* Remove left margin from first link */
        }
        
        /* Style first row of table */
        table tr:first-child {
            background: #2c3e50;
            color: white;
        }
        
        /* Note: :first-child can fail if element type doesn't match */
        .container span:first-child {
            background: yellow;
        }
    </style>
</head>
<body>
    <ul>
        <li>First item (bold, red)</li>
        <li>Second item</li>
        <li>Third item</li>
    </ul>
    
    <nav>
        <a href="#">Home</a>
        <a href="#">About</a>
        <a href="#">Contact</a>
    </nav>
</body>
</html>
```
**Why**: The `:first-child` pseudo-class targets the first element among siblings, commonly used for styling navigation links, list items, and table headers differently from subsequent elements.

        .hero {

    <section class="hero">
        <h1>Welcome to Our Site</h1>

        .light { font-weight: 300; }     /* Light */
        .normal { font-weight: 400; }    /* Normal (default) */
        .medium { font-weight: 500; }    /* Medium */
        .semibold { font-weight: 600; }  /* Semi-bold */
        .bold { font-weight: 700; }      /* Bold */
        .extrabold { font-weight: 800; } /* Extra-bold */
        .black { font-weight: 900; }     /* Black/Heavy */
        
        /* Keyword values */
        .keyword-normal { font-weight: normal; }  /* Same as 400 */
        .keyword-bold { font-weight: bold; }      /* Same as 700 */
        
        /* Relative values */
        .relative-lighter { font-weight: lighter; }  /* One step lighter than parent */
        .relative-bolder { font-weight: bolder; }    /* One step bolder than parent */
        
        /* Practical example: heading hierarchy */
        h1 { font-weight: 800; }
        h2 { font-weight: 700; }
        h3 { font-weight: 600; }
        p { font-weight: 400; }

        @font-face {
            font-family: 'Roboto';

            font-weight: 700;

## 8. js_promise_catch

```javascript
/**
 * PROBLEM: Handle promise rejections gracefully
 * TIME: O(1) SPACE: O(1)
 */

// Basic catch usage
fetch('https://api.example.com/data')
    .then(response => response.json())
    .then(data => console.log(data))
    .catch(error => {
        // Handles any error in the chain
        console.error('Fetch failed:', error.message);
    });

// Catch with error type checking
fetch('/api/user')
    .then(response => {
        if (!response.ok) {
            throw new Error(`HTTP ${response.status}: ${response.statusText}`);
        }
        return response.json();
    })
    .then(user => displayUser(user))
    .catch(error => {
        if (error.message.includes('404')) {
            showNotFound();
        } else if (error.message.includes('401')) {
            redirectToLogin();
        } else {
            showGenericError(error);
        }
    });

// Multiple catch handlers in chain
Promise.resolve()
    .then(() => {
        throw new Error('First error');
    })
    .catch(err => {
        console.log('Caught first:', err.message);
        return 'recovered';  // Return value continues the chain
    })
    .then(value => {
        console.log('Got:', value);  // "Got: recovered"
    });

// Catch with finally (cleanup)
loadData()
    .then(data => processData(data))
    .catch(error => {
        console.error('Error:', error);
        showErrorToast(error.message);
    })
    .finally(() => {
        // Always runs, regardless of success/failure
        hideLoadingSpinner();
    });

// Async/await equivalent
async function fetchData() {
    try {
        const response = await fetch('/api/data');
        const data = await response.json();
        return data;
    } catch (error) {
        console.error('Failed to fetch:', error);
        throw error;  // Re-throw if caller should handle
    }
}

// Catch returns a new promise, allowing recovery
getUser(123)
    .catch(error => {
        // Return default user on error
        console.warn('Using default user');
        return { id: 0, name: 'Guest' };
    })
    .then(user => {
        // Will receive either real user or default
        renderProfile(user);
    });
```
**Why**: `.catch()` provides centralized error handling for promise chains, enabling graceful degradation, error logging, and recovery strategies without deeply nested callbacks.

## 9. js_array_splice

```javascript
/**
 * PROBLEM: Add/remove elements at any position in an array
 * TIME: O(n) where n = array length (elements may shift) SPACE: O(k) where k = removed elements
 */

// Syntax: array.splice(startIndex, deleteCount, item1, item2, ...)
// Returns: array of removed elements (mutates original array)

const fruits = ['apple', 'banana', 'cherry', 'date'];

// Remove elements
const removed = fruits.splice(1, 2);  // Start at index 1, remove 2
console.log(removed);  // ['banana', 'cherry']
console.log(fruits);   // ['apple', 'date']

// Insert elements (deleteCount = 0)
const colors = ['red', 'blue'];
colors.splice(1, 0, 'green', 'yellow');  // Insert at index 1
console.log(colors);  // ['red', 'green', 'yellow', 'blue']

// Replace elements
const nums = [1, 2, 3, 4];
nums.splice(1, 2, 'two', 'three');  // Remove 2 elements, insert 2 new
console.log(nums);  // [1, 'two', 'three', 4]

// Remove from end (negative index)
const items = ['a', 'b', 'c', 'd'];
items.splice(-2);  // Remove last 2 elements
console.log(items);  // ['a', 'b']

// Practical: Insert at beginning
const queue = [2, 3, 4];
queue.splice(0, 0, 1);  // Same as unshift(1)
console.log(queue);  // [1, 2, 3, 4]

// Practical: Remove all after index
const tasks = ['task1', 'task2', 'task3', 'task4'];
tasks.splice(2);  // Remove from index 2 to end
console.log(tasks);  // ['task1', 'task2']

// Practical: Move element in array
function moveElement(arr, from, to) {
    const [element] = arr.splice(from, 1);
    arr.splice(to, 0, element);
    return arr;
}
const letters = ['a', 'b', 'c', 'd'];
moveElement(letters, 0, 2);  // Move 'a' to index 2
console.log(letters);  // ['b', 'c', 'a', 'd']

// Practical: Filter in place (keep only even numbers)
const numbers = [1, 2, 3, 4, 5, 6];
for (let i = numbers.length - 1; i >= 0; i--) {
    if (numbers[i] % 2 !== 0) {
        numbers.splice(i, 1);
    }
}
console.log(numbers);  // [2, 4, 6]
```
**Why**: `splice()` is the Swiss Army knife of array manipulation—insert, remove, or replace at any position. It mutates the original array and returns removed elements for potential use.

## 10. js_object_assign

```javascript
/**
 * PROBLEM: Copy properties from source objects to target object
 * TIME: O(n) where n = total properties SPACE: O(1) for shallow copy
 */

// Basic usage: merge objects
const target = { a: 1, b: 2 };
const source = { b: 3, c: 4 };
const result = Object.assign(target, source);
console.log(result);  // { a: 1, b: 3, c: 4 }
console.log(target);  // Same as result (target is mutated!)
console.log(result === target);  // true

// Create new object (don't mutate original)
const defaults = { theme: 'light', fontSize: 14 };
const userPrefs = { fontSize: 16 };
const config = Object.assign({}, defaults, userPrefs);
// config: { theme: 'light', fontSize: 16 }
// defaults remains unchanged

// Multiple sources (later properties override earlier)
const merged = Object.assign({}, 
    { a: 1 }, 
    { b: 2 }, 
    { a: 100, c: 3 }
);
console.log(merged);  // { a: 100, b: 2, c: 3 }

// Shallow copy only (nested objects are references)
const original = { 
    name: 'John',
    address: { city: 'NYC' }
};
const copy = Object.assign({}, original);
copy.name = 'Jane';           // Safe - doesn't affect original
copy.address.city = 'LA';     // WARNING - affects original!
console.log(original.address.city);  // 'LA' (mutated!)

// Deep copy alternative (for nested objects)
const deepCopy = JSON.parse(JSON.stringify(original));

// Practical: function options pattern
function createUser(options) {
    const defaults = {
        name: 'Anonymous',
        email: '',
        role: 'user',
        active: true
    };
    return Object.assign({}, defaults, options);
}
const user = createUser({ name: 'Alice', role: 'admin' });
// { name: 'Alice', email: '', role: 'admin', active: true }

// Practical: extend object with methods
const base = { x: 10, y: 20 };
Object.assign(base, {
    sum() { return this.x + this.y; },
    multiply() { return this.x * this.y; }
});
console.log(base.sum());       // 30
console.log(base.multiply());  // 200

// ES6 spread equivalent (often preferred now)
const spreadMerge = { ...defaults, ...userPrefs };
// Same result as Object.assign({}, defaults, userPrefs)

// Cloning arrays (since arrays are objects)
const arr = [1, 2, 3];
const arrCopy = Object.assign([], arr);
arrCopy.push(4);
console.log(arr);      // [1, 2, 3] (unchanged)
console.log(arrCopy);  // [1, 2, 3, 4]
```
**Why**: `Object.assign()` merges object properties, implements default options patterns, and creates shallow copies. For immutability, ES6 spread `{...obj}` is often preferred for readability.
